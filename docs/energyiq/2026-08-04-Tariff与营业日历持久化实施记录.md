# EnergyIQ Tariff 与营业日历持久化实施记录

## 1. 已完成边界

`packages/metadata/src/energyiq-operational-policy-store.ts` 已建立独立的 Operational Policy 深模块，负责：

- 发布不可变 Tariff Schedule Revision；
- 发布不可变 Operating Calendar Revision；
- 激活供新分析使用的一对 Project Policy 版本；
- 按 Project、Scope、左闭右开 Period 和 Interval Fact 解析 Cost、Operating 与 Standby；
- 为 Published Project Release 提供严格的版本固定入口。

本批未修改 `energy-analysis.ts`、Project Analysis Resolver、API 或 Web Renderer。正式 Overview 仍需由集成任务把 Release 固定的版本和已有 Interval Fact 传给本模块；在该集成完成前，不能宣称客户 Cost/Operating 页面已正式打通。

## 2. 持久化模型

SQLite 新增：

| 表 | 语义 |
| --- | --- |
| `energyiq_tariff_schedule_revisions` | Project 级不可变 Tariff Revision，内部包含 Project/Scope-owned 生效费率条目 |
| `energyiq_operating_calendar_revisions` | Project 级不可变 Calendar Revision，冻结发布时的 Project timezone、周营业时间和日期例外 |
| `energyiq_operational_policy_bindings` | 当前 Project 激活的 Tariff/Calendar 版本对；只用于新分析，不改写历史结果 |

Revision 表拒绝 `UPDATE` 和 `DELETE`。绑定表通过 `(project_id, version_id)` 组合外键同时约束 Project 和版本，不能把 Project B 的版本绑定给 Project A。`version_id` 仍保持全局主键。

## 3. Project/Scope 与生效规则

一个 Revision 是 Project-wide 的不可变集合；集合内每个条目显式拥有以下 Owner 之一：

```ts
type EnergyIqPolicyOwner =
  | { kind: "project" }
  | { kind: "scope"; scope_id: string };
```

解析指定 Scope 时使用“最近 Scope 祖先覆盖 → Project 默认”的优先级。Scope 链必须完整回到当前 Project root；缺父节点、跨 Project 父节点或环依赖直接失败，不能静默把损坏链补成 Project root。

Tariff 使用带时区偏移的生效时刻，并按分析 Period 内实际生效片段计费。每个 Revision 内 Tariff entry id 唯一；相邻片段不会只因 id 相同而合并。若一个 Period 的有效片段出现多个币种，Cost 返回 `TARIFF_CURRENCY_CONFLICT`，不执行隐式换汇。

Operating Calendar 使用 Project timezone 的本地日期、七日周表和日期例外。空时间窗表示明确关闭；缺 Calendar 不等于全天营业或全天关闭。跨营业边界的 Interval Fact 按实际重叠时长分配 Operating/Standby kWh。

## 4. 运行来源必须显式二选一

`evaluateAnalysisPolicy()` 不接受两个独立 optional version。调用方必须选择完整来源：

```ts
type EnergyIqOperationalPolicySource =
  | { mode: "active" }
  | {
      mode: "release-pinned";
      tariff_schedule_version: string;
      business_calendar_version: string;
    };
```

- `active`：同时读取当前 Project 激活的两个版本，供新的未保存分析使用；
- `release-pinned`：Tariff 和 Calendar 必须同时由同一个 Release 上下文提供；
- 缺一个版本、继续传旧式顶层 version 字段或混合两种来源时抛出 `ENERGYIQ_OPERATIONAL_POLICY_SOURCE_INVALID`；
- Release 固定版本不存在时返回对应 `Unavailable`，绝不回退到 active 版本。

这条约束防止历史分析出现“旧 Tariff + 当前 Calendar”或“当前 Tariff + 旧 Calendar”的混合口径。

## 5. 显式 Unavailable

| 场景 | reason code |
| --- | --- |
| 未激活 Tariff | `TARIFF_VERSION_MISSING` |
| Release Tariff 不存在/不归属 Project | `TARIFF_VERSION_NOT_FOUND` |
| Tariff 未覆盖完整 Period | `TARIFF_NOT_EFFECTIVE_FOR_PERIOD` |
| 有效片段币种冲突 | `TARIFF_CURRENCY_CONFLICT` |
| Cost 没有 Interval Fact | `COST_FACTS_UNAVAILABLE` |
| 未激活 Calendar | `OPERATING_CALENDAR_VERSION_MISSING` |
| Release Calendar 不存在/不归属 Project | `OPERATING_CALENDAR_VERSION_NOT_FOUND` |
| Calendar 未覆盖完整 Period | `OPERATING_CALENDAR_NOT_EFFECTIVE_FOR_PERIOD` |
| Operating/Standby 没有 Interval Fact | `OPERATING_FACTS_UNAVAILABLE` |

没有任何 SGD、费率、营业时间或关闭状态的静默默认值。

## 6. 历史结果语义

Admin 发布并激活 v2 后，`active` 新分析读取 v2。历史 Saved Analysis 保存当时完整结果与版本；重新打开不会调用 active 重算。需要重跑时应由新的 Project Release/Run 创建新结果，不覆盖旧 Run。显式 `release-pinned` v1 仍只解析 v1。

## 7. 验证证据

- Tariff 跨生效边界、币种和版本输出；
- Scope 祖先 Tariff/Calendar 覆盖；
- Asia/Singapore UTC→本地营业时间、节假日例外和跨边界用量分配；
- 缺版本、缺生效覆盖、币种冲突和缺 Operating Fact 的 `Unavailable`；
- active v2、Release-pinned v1 和 Saved Analysis v1 不互相改写；
- partial Release source、重复 Tariff entry id、跨 Project Scope parent 和跨 Project binding 全部 fail closed。
