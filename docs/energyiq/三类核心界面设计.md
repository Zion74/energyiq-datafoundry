# EnergyIQ 三个核心任务界面与 Data Map

## 1. 全局 Shell

顶部顺序：

~~~text
EnergyIQ | Project selector | Overview | Project Explorer | AI Analyst | Data Map | Admin* | Account
~~~

Admin 仅管理员可见。界面默认英文。Project selector 是全局上下文，切换后当前页面必须重新请求对应 Project 的内容，不能只改选择器文字。

Water 未配置时不显示资源选项。顶部始终显示数据更新时间和 provisional/stale 状态。

## 2. Overview

**任务：** 让 Boss/FM 快速知道先处理什么。

### 布局

- 左侧：粘性章节目录；
- 主区：建议、KPI、比较、时间模式和 Evidence；
- 页头：Scope、Period、Resource、Run。

左侧目录：

1. Overview；
2. Benchmarks；
3. Standby wastage；
4. Operating hours；
5. Forecast preview。

### 信息优先级

1. Executive Action Summary；
2. 数据新鲜度和质量；
3. 总耗能、日均、峰值、可选费用；
4. 自身历史；
5. 同 Tier 比较与归一化比较；
6. 非营业时段；
7. 异常与 Evidence；
8. Forecast Preview。

图表必须回答一个决策问题。没有可执行含义的炫酷图不进入模板。

### 操作

- Yesterday / Last 7 days / Last 30 days / Custom；
- 选择 Scope；
- 点击 Run 创建 Analysis Run；
- 点击节点进入 Explorer；
- 点击 Investigate with AI 进入完整 AI Analyst。

## 3. Project Explorer

**任务：** 让 FM 按项目真实结构核查 Scope、Meter、组成和质量。

### 桌面布局

- 左：可搜索的 Scope Tree；Meter Point 作为挂载项而非 Tier；
- 中：所选 Scope/Meter 的总量、趋势、子项和构成；
- 右：异常、建议、质量、来源、Evidence、AI 入口。

### Scope 选择

选择 Project 或非叶子 Node：

- 子 Tier 卡片和排名；
- 同 Tier 横向比较；
- 当前 Scope 自身历史；
- load/aircon/light/other；
- 直接挂载 Meter；
- Tier × Tier / Tier × Time 切片。

选择叶子 Node：

- 当前节点总量和历史；
- 计量点构成；
- 分类与时间模式；
- 数据质量。

选择 Meter Point：

- 实体/虚拟；
- total/component/standalone/official；
- 最后读数与区间能耗；
- 原始累计曲线和区间曲线；
- 公式或 Source Binding；
- 质量事件。

### 热力图

当结构支持时，通用切片器可生成：

1. Tier A × Tier B；
2. Tier × Time；
3. Node × Time。

不要求每个 Project 都有 Floor/Room，也不为空的业务层创建假节点。

## 4. AI Analyst

**任务：** 回答模板外的问题，并使计算过程可验证。

直接挂载 DataFoundry DataTasksApp，保留：

- 会话和追问；
- 文字、表格、图表；
- Artifact Preview；
- Task Console；
- Evidence、Trace；
- Files、Knowledge 引用。

来自 Overview/Explorer 的入口携带：

- Project；
- Scope；
- Tier；
- Resource；
- Period；
- Data/Hierarchy/Metric/Template 版本。

Task Console 展示范围解析、数据覆盖、使用的 Meter、差分/指标、查询和输出，不展示模型私有推理。用户在会话内改变 Scope/Time 时，服务端重新解析。

不复制 DataTasksApp，不使用 iframe，不在右下角再做一套完整聊天。

## 5. Data Map

**任务：** 让用户理解“数据从哪里来、如何连到当前分析”。

user 只读查看：

- Project/Tier/Scope；
- Meter Point；
- Source Binding；
- total/component/virtual 关系；
- business category；
- Metric 与 Knowledge 引用；
- configured/inferred 与可信状态。

admin 从后台进入编辑/诊断视图。

## 6. 角色动线

Boss：

~~~text
Overview → action/evidence → optional Explorer → AI Analyst
~~~

FM：

~~~text
Overview exception or Explorer → scope/meter verification → AI Analyst
~~~

两者权限相同。

## 7. 状态

| 状态 | UI |
| --- | --- |
| Draft Project | 仅 admin 可见 |
| Provisional metadata/mapping | 明确标签，不当作正式结论 |
| No data | 说明等待首次导入 |
| Partial | 展示覆盖率和受影响模块 |
| Stale | 显示最后成功日期 |
| Failed run | 保留上次成功结果，可重试 |
| Insufficient history | 隐藏历史异常/Forecast |
| No tariff/area/people | 隐藏对应 Cost/EUI/per-person |

## 8. 当前原型与目标

当前已存在 Overview、Explorer、AI Analyst、Data Map、Admin 路由，AI Analyst 已复用 DataTasksApp，并有服务端 Energy Query Context 与样板事实。

仍需：

- Tier Definition 取代自由 node_type；
- Meter Point 从空间节点分离；
- Ngee Ann 移除 Block Test；
- Preschool 区分 provisional Centre fixture 与三层目标；
- Project/Tier Template 和 Analysis Run 持久化；
- 去除硬编码 Tariff；
- 所有页面完全消费已发布配置。
